Foundational Infrastructure

DNS & NTP Appliances

Dedicated DNS and time infrastructure designed around separate trust domains, controlled exposure, hardened Linux appliances, and validation-before-access.

View Project Repository

Objective

DNS and NTP are foundational services. Because many systems depend on them, the project treats their trust relationships as an architectural decision rather than assuming that foundational services should be shared broadly.

Architecture

dns-time-lab01 Homelab, infrastructure, security, and management systems
dns-time-home01 Household and consumer systems

The appliances do not provide cross-domain failover and do not administer one another. This preserves the separation between higher-trust infrastructure and household systems.

Design principle: foundational services should not automatically receive foundational trust.

Key Technologies

  • Debian
  • Unbound
  • Chrony
  • Ansible
  • nftables
  • AppArmor
  • auditd

Validation-First Rollout

  • DNS initially bound only to loopback interfaces
  • DNSSEC behavior validated before client exposure
  • Chrony synchronization verified independently
  • Listening ports checked before access rules are introduced
  • Network exposure added incrementally only after runtime validation
Design philosophy: validate first, expose last.

What This Project Demonstrates

Linux Infrastructure

Minimal service-focused systems with deliberately constrained exposure.

DNS & Time Services

Recursive DNS, DNSSEC validation, time synchronization, and service policy.

Trust Design

Separate service domains instead of allowing convenience to erase trust boundaries.

Reproducibility

Configuration and validation designed to be documented and automated over time.
